N-ATLAS Launchpad · Submission document

Technical documentation

Architecture, setup, deployment and usage of N-ATLAS Launchpad — enough for an independent team to run it, host it and build on it.

Live app: https://n-atlas-sites.vercel.app  ·  Code: https://github.com/lumpyspace/N-atlas-launchpad (branch: blocks)
Stack: Node.js + Express + TypeScript (backend) · React + Vite + Tailwind (frontend) · N-ATLAS on vLLM · Groq · Upstash Redis · Vercel

01What it is

Launchpad is the shortest path from an idea, described in a Nigerian language, to something real built on N-ATLAS.

  • Simple mode — for business owners: describe the business → Launchpad plans it → Groq drafts a website (pages, theme, plugins: price list, orders, WhatsApp contact, FAQ) → the owner checks every page → one click publishes it to a link, with an N-ATLAS assistant on every page that answers customers in English, Pidgin, Yoruba, Hausa or Igbo. Orders land in an inbox. Owners can add languages (N-ATLAS translates the whole site), write blog posts, and choose a theme.
  • Advanced mode — for developers: the same, plus a prompt studio, live playground, test suites per use case, a security attack suite with automatic hardening, side-by-side model comparison, and an SDK (JavaScript and Python) for calling N-ATLAS from their own apps.
  • A helper on every page answers questions about Launchpad itself; the whole interface is translated into Pidgin, Yoruba, Hausa and Igbo.

Design choices

  • One N-ATLAS interface. Everything reaches the model through NAtlasProvider; hosting changes are an .env change.
  • Each model where it is strong. Groq plans and decides; N-ATLAS understands and speaks Nigerian languages; every N-ATLAS line is checked, with Groq as a per-line fallback, and each reply records who spoke it.
  • No invented facts. Draft pages are “Draft by Groq — check it”; the assistant only uses pages the owner has checked, and blanks (…) are left out.
  • Safe by default. Every assistant's instructions are hardened and carry a hidden reference code; replies that would leak it are replaced. Owners hold a secret edit key (stored hashed) instead of accounts. Public servers rate-limit per IP and per site.

03Run it locally

Requirements: Node.js 20 or newer (tested on 24), npm, and an N-ATLAS endpoint (section 05). A Groq key is free at console.groq.com.

git clone -b blocks https://github.com/lumpyspace/N-atlas-launchpad.git
cd N-atlas-launchpad
npm install --prefix backend && npm install --prefix frontend
# then fill in NATLAS_* and GROQ_API_KEY:
cp backend/.env.example backend/.env
# API on http://localhost:8788
npm run dev --prefix backend
# app on http://localhost:5174 (it proxies /api to the backend)
npm run dev --prefix frontend
# proves app → N-ATLAS → reply
cd backend && npm run healthcheck

04Host it (Vercel + Upstash)

  1. Import the repository into Vercel. vercel.json builds the frontend and serves the API from api/index.mjs (one function); routes /a/* to the app.
  2. Create a free Upstash Redis database and copy its REST URL and token.
  3. In Vercel → Settings → Environment Variables (Production) add: NATLAS_PROVIDER=http, NATLAS_ENDPOINT, NATLAS_MODEL, NATLAS_API_KEY, NATLAS_REPETITION_PENALTY=1.12, NATLAS_REQUEST_TIMEOUT_MS=280000, GROQ_API_KEY, UPSTASH_REDIS_REST_URL, UPSTASH_REDIS_REST_TOKEN (and optionally GEMINI_API_KEY). Values are read with quotes or a pasted NAME= forgiven.
  4. Deploy, then open /api/health and /api/sites/status (should say "canPublish": true).

05Serve N-ATLAS

On a GPU with Modal (what the live app uses)

pip install modal && modal setup
modal secret create natlas-hf HF_TOKEN=<Hugging Face token that accepted the N-ATLaS licence>
modal secret create localizekit-natlas NATLAS_API_KEY=<a long random key>
# MIN_CONTAINERS=1 modal deploy … keeps one GPU warm
modal deploy inference/modal_natlas.py

Then NATLAS_ENDPOINT=https://<workspace>--localizekit-natlas-serve.modal.run/v1, NATLAS_MODEL=NCAIR1/N-ATLaS and the key above. The script serves the unmodified weights with vLLM on an L4 (24 GB) in BF16 with an 8k context.

On a laptop with Ollama (slow, offline)

Convert the gated weights to GGUF and create the model from inference/Modelfile (steps in inference/README.md), then NATLAS_ENDPOINT=http://localhost:11434/v1, NATLAS_MODEL=n-atlas. On a CPU expect around a token per second.

09Limits and troubleshooting

  • “Waking up N-ATLAS” — the GPU scaled to zero; the first reply waits a few minutes. Keep it warm with MIN_CONTAINERS=1 while people are testing.
  • Groq’s free plan allows about 8,000 tokens a minute per model; Launchpad spreads work over three Groq models and falls back to Gemini. For many simultaneous users, upgrade the Groq plan.
  • Publishing says it isn't set up — the Upstash variables are missing on a public server; /api/sites/status shows it.
  • No accounts by design — projects live in the browser; a site is edited with its secret owner key, stored in that browser.
  • Scope — small websites with an assistant (information, prices, orders, contact, blog); no customer accounts or online payments.
